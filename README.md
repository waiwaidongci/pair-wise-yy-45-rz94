# 服装品牌打样开发与版型修订工作台

为服装产品开发团队提供款式档案、样品轮次、尺寸实测、部位批注、替代改版方案、审核锁定和修订历史。

## 技术栈

React + MUI + Redux Toolkit + React Router + MSW（模拟协作服务端）+ Vite + TypeScript

## 本地运行

```bash
npm install
npm run dev      # http://localhost:62045
npm test         # 协作协议与 HTTP 集成测试（node:test + MSW node）
npm run build
```

## 可恢复协作模型

尺寸、批注、草稿、改版方案不再只存在浏览器，而是通过带修订号的协作协议与服务端同步。

- **修订号 revision（R#）**：服务端对每件样衣单调递增；`review.unlock` 不占修订号，表示开启新修订分支。
- **操作号 seq / opId（#0001）**：本地每个编辑都生成一条操作（新增批注、批注状态、留言、方案决定、草稿、锁定/解锁），带本地顺序号与全局幂等键，整条队列持久化在 localStorage。
- **按序合并**：`POST /api/samples/:id/sync` 一次提交一批操作，服务端按数组顺序逐个应用并返回每个 opId 的 `applied` / `rejected`；重复提交相同 opId 只重放、不产生第二个修订号。
- **他人修改不覆盖**：服务端领先于操作的 `baseRev` 时，新增类操作（批注/留言）自动并行追加；同一批注状态、同一方案决定、同一作者草稿出现分歧时返回 `conflict` 并附带对方值。本地操作与冲突状态全部保留，同步面板逐项显示「本地 / 服务端」差异，可选择「以我的为准（force 重试）」或「采用服务端版本」。
- **断网与失败**：离线时编辑照常进入本地持久化队列；恢复联网后自动按操作号顺序同步。服务端故障（如模拟 503）后未完成操作保留，可手动重试，不丢任何内容。
- **旧草稿迁移**：首次启动检测旧键 `garment-sampling-draft-v1`，把新增批注/留言、方案决定、草稿正文、锁定状态逐条翻译成带修订号的迁移操作（`migrated` 标记），旧数据备份到 `garment-sampling-draft-v1-backup`，迁移结果在页面顶部提示。
- **审核锁定快照**：锁定时服务端冻结当前修订（尺寸、批注、方案、决定）并生成只读 `ReviewSnapshot`；冻结期间除解锁外的写操作一律返回 `locked`。本地被冻结的操作转为 `blocked` 不自动重试；解锁开启新分支后可重试，历史快照永久保留可查看。

### 协作演练

左侧「协作与修订同步」面板提供：模拟断网 / 恢复、模拟下次同步失败（503）、以及以版师或供应商身份制造他人修改（批注状态、方案采纳、留言、草稿），用于演示冲突检测、逐项差异与失败重试。

## 核心工作流

- 从款式档案进入开发轮次，维护尺码、面辅料、色卡和工艺要求。
- 对比两轮尺寸实测，自动高亮超出容差的部位并关联试穿意见。
- 点击样衣图片部位添加批注，或由版师提交替代方案和责任人。
- 负责人采纳方案、保存按作者隔离的评审草稿；多人同时编辑时冲突逐项合并不互相覆盖。
- 审核完成后锁定轮次、冻结同次评审快照，修订历史保留完整操作日志。
